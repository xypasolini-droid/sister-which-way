## 被替换的结构

0.4.2 把大多数现实路线归入 `lantern`，再按课堂、分住、救父未成、借宿、继续劳动变标题与尾声；两个成年梦境则在最后任意选。用户明确指出这仍是“类别下面换标题和文案”，要求前面的行为改变命运，五个终幕也须明显不同。

本版已替换这套结构：**七次决定、五种固定命运、五幅独立整场插画**。不再保留第03下面五个文案子类，不用旧的 660／84／12 路径统计解释新版，也不把状态或路径数量当作玩家发生概率。旧完成档只做明确标示的历史保留。

## 必须通过的规则检查

1. **撤离反事实**：同样的前六个行动，`register` 得到 02、女主登车、姐姐在身边；改选 `child` 得到 03、女主未登车、姐姐离开、莱拉同行。
2. **救父的前置**：`guardBond` 与 `pact` 同时成立才可 `release`。一次问讯不能产生读写往来；n18 不能临时补送 `pact`；没有先约好时限，补传消息会错过侧门。
3. **童话的不同根源**：04 需要先保护别人；05 需要先教字、获准记录或共同照护。共同遭受的母亲伤势和单纯希望值不算玩家已经做过行动。
4. **流程长度与退路**：每条新版合法路线七次决定。第七步直接结算，不出现无意义第八次点击；不满足救父或梦境条件仍有现实路径可执行。
5. **固定内容**：同一新结局 ID 只返回一种标题、代价和故事结果。03 不再包含五个子类。
6. **状态可信与兼容**：只能合法行动重放得到结局。旧完成档标作旧版，不假装发生新版分别或引路人生涯；进行中旧短篇只迁移仍然合法且含义一致的前缀。
7. **梦境隔离**：现实父亲未获救、家人已离城、女主与莱拉留城的事实，在04和05中仍可查明。梦中未来不能自动治疗或带回现实的人。

合法五条示例见[实际流程与路线](STORY-FLOW.md)。主屏维持简短对白，完整命运与代价进入手记；不能只靠打开长篇文档才知道家人究竟去了哪里。

最终工程验证：**17个测试文件、202项测试全部通过**；`npm run typecheck`、`npm run build`均通过。规则穷举使用真实的`createInitialState`、`getChoices`与`choose`，共610条合法完整路线、1052个含过程与终态的组合：每条路线第七次行动结算，五种结局均可达，没有无路可走的中间状态。这是路线计数，不是玩家发生概率。

## 影片与原创的界线

本轮局部复看了母亲被催离、坚持找女儿、负伤父亲与木推车等片段帧，实际时间码见[细节审计](DETAIL-AUDIT.md)。01明确五人重聚、02四人随舅舅离城、03成年引路人及两个自治童话均是游戏原创分岔。尤其03的数年后不能列为电影原有结尾，也不保证战争中的秘密山路安全。
